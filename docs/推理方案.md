# 两阶段推理方案

YOLO 负责整图检测，UNet++ 对每个外扩后的检测框做二值分割，再把掩码贴回原图。两个模型都用 TensorRT FP16 engine 推理，输入输出保持 FP32。置信度和 IoU 在推理时传入，不写进 engine。

测量环境：NVIDIA GeForce RTX 4060 Laptop GPU，TensorRT 10.16，Ultralytics 8.4。样例图 `data/images/val/0006.jpg`（640×640，4 个目标）。下面的耗时都是预热之后的单张端到端时间。

## 用法

```text
python export_engines.py
python infer.py --source data/images/val/0006.jpg --conf 0.25 --iou 0.7
```

只重建 YOLO engine 时：

```text
python export_engines.py --only yolo --force
```

`--conf` 是本次置信度阈值，`--iou` 只用于带 NMS 的检测模型。把 `--conf` 调到 `0.99` 时，`0006.jpg` 会去掉置信度 0.98 的矩形，只保留 3 个框。

## 导出

`export_engines.py` 把微调权重导出成 engine。

YOLO 始终 `nms=False`，不传入 `conf`、`iou`、`max_det`。导出时读取 `model.model.end2end`，并在 `best.engine.json` 写入：

- `end2end`：是否为端到端模型
- `names`：类别名
- `imgsz`：输入边长，当前为 640
- `nms_in_graph`：固定为 `false`

这样运行时可以任意提高或降低阈值。若把 `nms=True` 且 `conf=0.25` 写进 engine，图里的 Efficient NMS 会先丢掉 0.25 以下的框，推理时只能再提高阈值，不能再降低。

UNet++ 走 ONNX opset 17，再构建 FP16 engine。输入名 `images`，输出名 `logits`，动态 batch 为 1 / 4 / 8，空间尺寸 256。配置写在 `runs/seg/best.engine.json`。

## 推理路径

实现在 `yolo_runtime.py` 和 `infer.py`。一张图只上传一次 GPU，检测和分割共用这块显存里的 BGR 图像。

1. 读图后，把 uint8 BGR 经 pinned memory 上传到 GPU。
2. YOLO 前处理在 GPU 上做 letterbox，规则与 Ultralytics `LetterBox(center=True)` 一致：按短边缩放，居中填充 114，再除以 255 变成 RGB。送入 engine 前必须 `contiguous()`，否则 TensorRT 会按错误内存读出空检测。
3. YOLO engine 前向。计算是 FP16，绑定输入是 FP32，因此加载时 `fp16=False`，避免把输入再转成 FP16。
4. 按模型类型在 GPU 上过滤，见下一节。框用 `scale_boxes` 映回原图像素。
5. 按检测框外扩 0.15 得到 ROI。在已上传的图像上切片，GPU 双线性缩放到 256，除以 255 后做 ImageNet 归一化（均值 `0.485, 0.456, 0.406`，标准差 `0.229, 0.224, 0.225`），与 SMP `get_preprocessing_fn("resnet34", "imagenet")` 一致。
6. UNet++ engine 输出 logits，按阈值 0.5 得到掩码并贴回原图。类别颜色来自 YOLO 的类别 id。
7. 可视化只在前景像素上做 uint8 整数混合，不再把整图转成 float32。JPEG 用 `simplejpeg`（libjpeg-turbo，quality 85，`fastdct=True`），掩码 PNG 压缩级别为 1。

## 检测过滤

| 模型 | 导出 | engine 输出 | 推理时过滤 |
|---|---|---|---|
| YOLO11 等带检测头、需要 NMS 的模型 | `nms=False`，`end2end=false` | `(1, 4+nc, 8400)`，本项目 3 类为 `(1, 7, 8400)` | GPU 上调用 Ultralytics `non_max_suppression`。先 `import torchvision`，使其走 `torchvision.ops.nms`。使用本次 `--conf` 和 `--iou` |
| YOLO26 等端到端、没有 NMS 的模型 | `nms=False`（Ultralytics 也会强制关闭） | `(batch, keep, 6)`，内容为 xyxy、conf、cls | 只在 GPU 上保留 `score > conf`，不再做 NMS |

输出最后一维是 6 且候选数不超过 300 时，也按端到端结果只滤置信度。空白图不会进入 NMS 内核；加载 engine 时会用一小批高分框预热 `torchvision.ops.nms` 和 `scale_boxes`，避免第一张真实图片的后处理多出几十毫秒。

## 耗时

同一张 `0006.jpg`，4 个目标，掩码像素 4459 / 10906 / 7512 / 7728。

| 阶段 | 两个 engine，CPU 后处理 | 阈值写入 engine | 当前方案 |
|---|---:|---:|---:|
| 读图 | — | 4.91 ms | 3.15 ms |
| YOLO 检测 | 13.60 ms | 10.69 ms | 4.12 ms |
| YOLO 前处理 | — | 2.37 ms | 0.49 ms |
| YOLO 推理 | 2.09 ms | 7.12 ms（含图内 NMS） | 2.11 ms |
| YOLO 后处理 | 8.85 ms | 0.76 ms | 1.51 ms（GPU NMS） |
| ROI 裁剪 | — | 0.10 ms | 0.07 ms |
| 分割前处理 | — | 5.97 ms | 0.94 ms |
| UNet++ | 10.24 ms | 8.35 ms | 7.44 ms |
| 掩码回贴 | — | 0.95 ms | 0.75 ms |
| 可视化保存 | 22.27 ms | 9.58 ms | 6.90 ms |
| 端到端 | 59.96 ms | 41.20 ms | 23.61 ms |

当前方案相对「阈值写入 engine」少约 17.6 ms。多出来的主要是可调阈值的 GPU NMS（1.51 ms），换来的是推理时可以任意设置 `--conf` 和 `--iou`。
